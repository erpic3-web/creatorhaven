# CreatorHaven

A YouTube Studio power-up for a network of channels: one dashboard on the
official YouTube Data + Analytics APIs (exact totals, **engaged views**, watch
time, revenue, outliers, latest-upload ranking, content calendar, creator
alerts), a set of public creator tools, and a companion browser extension
(`extension\`) that adds features inside YouTube and Studio.

Working name; rename via `APP_NAME` in `sf\config.py`.

## Run

```
D:\Claude\studioforge\run.bat          → http://127.0.0.1:5800
python test\selftest.py                → hermetic tests (mock Google/Gemini/SponsorBlock)
```

Requirements: Python 3.12+ with `flask` (and `pillow` for the thumbnail
analyzer). No other packages.

## First-time setup (Google Cloud)

The site reuses the OAuth client the yt-schedule-bot already links channels
with (a **Desktop** client, so any loopback port works as the redirect). What
still has to be done once in the same Cloud project:

1. **Enable "YouTube Analytics API"** (APIs & Services → Library). The Data
   API is already enabled there. Without it every channel shows
   "enable the YouTube Analytics API" after a sync.
2. On the OAuth consent screen (published, "In production") make sure these
   scopes are allowed; the site requests them when you link a channel:
   - `youtube.readonly` (videos, scheduled uploads, stats)
   - `yt-analytics.readonly` (exact totals, engaged views, watch time)
   - `yt-analytics-monetary.readonly` (estimated revenue)
   - `youtube.force-ssl` (find & replace edits, comment replies)
3. **Request a quota increase** for the Data API (default 10,000 units/day;
   search costs 100, an edit 50). The dashboard shows the units used today.
4. Optional: a plain **API key** restricted to the Data API lets the public
   tools run without consuming a channel's OAuth token. Paste it in Settings.

Then in the site: Settings → **Import from yt-schedule-bot** (brings the four
already-linked channels with the read scope) and **Link channel with Google**
for each channel to add the analytics/revenue/edit scopes (same Google account,
pick the channel on the account chooser). Press **Sync**.

## Hosting on Render (2026-09-10)

The repo is Render-ready: `wsgi.py` (gunicorn entry), `requirements.txt`, `render.yaml`
(a Blueprint: one free web service + one free Postgres). Everything that matters is an
environment variable (see `sf/config.py` `_ENV`): `SITE_PASSWORD` (login gate),
`SECRET_KEY` and `EXT_TOKEN` (generated by the blueprint), `GEMINI_API_KEY`,
`YOUTUBE_API_KEY` (optional, but the niche radar and public lookups need it or an OAuth
token), `GOOGLE_CLIENT_ID` / `GOOGLE_CLIENT_SECRET` / `GOOGLE_CLIENT_TYPE`,
`DISCORD_WEBHOOK_URL`, `DATABASE_URL`, `SF_NO_PERSIST=1`. `BASE_URL` is optional: Render's
own `RENDER_EXTERNAL_URL` is used when it is empty.

**Durable data without porting the store.** The site keeps everything in one SQLite file
and a Render disk is not free, so `sf/persist.py` keeps that FILE durable: when
`DATABASE_URL` is set it restores the newest copy from a one-row `bytea` table in Postgres
before the store opens (integrity-checked first), then pushes a consistent snapshot
(`Connection.backup` → `serialize`) 8 s after any write-shaped `/api/*` call, every
`PERSIST_MINUTES` (10), and at interpreter exit. Settings → Site → Storage shows
"durable (Postgres backup, N pushes)" or "EPHEMERAL". Without a `DATABASE_URL` a hosted
deploy loses channels, tokens, ledger and chat on every restart.

**Linking channels on a hosted site with the Desktop OAuth client.** A Desktop client only
accepts loopback redirects, so when `base_url` is not loopback the auth URL redirects to
`http://127.0.0.1:5800/oauth/cb` on the user's own machine (a dead page, or the local
CreatorHaven if it is running, which will show "State mismatch"): copy the `code=` value
from that tab's address bar into Settings → "Hosted, or the callback did not come back?
Paste the code". A Web OAuth client with `https://<host>/oauth/cb` registered
(`GOOGLE_CLIENT_TYPE=web`) makes the round trip automatic. "Import from yt-schedule-bot"
only works on the PC that has the bot.

Still true after hosting: refresh tokens are stored in the clear inside the SQLite blob
(add per-user accounts + encryption before other creators log in), the public-signal
tools (monetization checker, analyzer signals) call YouTube's player endpoint and get
bot-checked from datacenter IPs, and the browser extension keeps talking to the LOCAL
site (its site URL setting is not exposed in the popup).

## Channel search (v0.2.0)
The header search bar finds any YouTube channel by name, @handle or URL (press `/` to focus).
Handles and URLs cost 1 quota unit; free-text searches cost 100 (of 10,000 per day) and are
cached for a day. Opening a result shows the channel page: subscribers / views / videos with
growth deltas, average and median views of the last 30 uploads, uploads per week, shorts share,
views per day of channel age, a bar chart of the last 30 uploads (orange = 2x the median),
and the recent-uploads table with views/day and outlier scores. "Track this channel" adds it
to the dashboard's public channels; the daily sync then records a snapshot per day, which is
where the 7-day / 30-day growth numbers come from. API: `/api/search/channels?q=` and
`/api/lookup/channel/<id>`.

## Creator Ledger design system (2026-09-10) — the whole ecosystem's theme

Every surface (web app, Chrome extension popup, injected thumbnail lightbox and on-page
tabs) now shares one legally-distinct system, deliberately NOT YouTube Studio's trade
dress: charcoal void `#161719`, steel-graphite panels `#1E2124`, 1px steel dividers
`#27272A`, burnt crimson `#A31D1D` used only for active/selected/focused states (active
nav underline, selected studio tab, checked toggles, primary-button keyline, focused
inputs), mint `#34D399` for up-trends and coral `#F43F5E` for down-trends, white primary
text with `#AAAAB2` secondary, one sans stack (Space Grotesk for labels/data/headings,
Inter for body — every serif and italic display face is gone), 2px corner radius on
everything (`--radius*` and `--pill` tokens are all 2px), zero drop shadows, and one
spring curve `cubic-bezier(.16,1,.3,1)` at 200 ms for every transition. Cards and buttons
lift 1.5% (`translateY(-2px) scale(1.015)`) with the border brightening to zinc-500, and
every list feed (channel cards, tool cards, launch rail, ledger rows, table rows, quick
actions, chips) dims its non-hovered siblings to 40%.

Component rules that changed with it: analytics tiles show the number first and the growth
at the very base of the card as `[ +4.2% Delta ]` (mint/coral); every chart is a single
1.5px platinum trail (`--trail`, `#E4E4E7`) over a zero-fill ground, secondary series in
zinc-500, outlier bars platinum on steel; the production ledger uses steel rows with
typographic stage tags (`[ STAGE.01 / IDEA ]` … `[ STAGE.03 / ACTIVE ]` in silver/white,
`[ COMPLETED ]` in mint, `[ STAGE.04 / REVISIONS ]` in coral); the Studio Brain canvas
keeps its centered stream and inline radar slates on steel with crimson markers. The only
script face left is the "How may I help you…" placeholder/greeting the user asked for in
cursive. The theme toggle still works: light is a mirror of the same system on `#f4f4f5`.
**Extension (same system, `extension/`):** popup is a 420 px envelope with a compressed sans
wordmark, steel `SF` chip, square checkboxes that fill crimson plus a `[ ON ]` / `[ OFF ]`
tag at the end of every toggle row (CSS `:has`), no connection/probe text anywhere (the
retained siteUrl/token/studioProbe inputs stay hidden). The thumbnail grabber's lightbox is
a theatre: `rgba(10,10,10,.9)` + 24 px blur backdrop, the image bounded by a 1 px hairline,
a top utility bar `COPY IMAGE // DOWNLOAD // CLOSE`, and DOWNLOAD opening an inline split
selector `[ DOWNLOAD ] ➔ RAW THUMBNAIL / TILE (WITH TITLE)` (same `doDownload` /
`doDownloadTile` functions; the tile composer is untouched). The on-page trigger is a thin
steel edge tab (vertical `GRAB` + 1 px camera) that turns crimson in grab mode; the Studio
`SF` tab, Discord tab, don't-recommend chip, star, sub badge, outlier badges and ad bar got
the same steel-tab treatment. `node test
un.js` 57/57; harness pages + rendered PNGs in
`extension/test/` (`harness_popup.html`, `harness_lightbox.html`, `shots/`). The unpacked
extension must be RELOADED in Chrome to pick the new CSS up.

The whole layer lives at the end of `static/style.css` ("CREATOR LEDGER"); the tokens at
the top of that file are the source of truth, and `tailwind/brain.css` pins the same
values for the Tailwind side (`amber-*`/`red-700` = crimson, `zinc-900` = steel).

## Studio Brain canvas (2026-09-10) — the chat layout

The Strategy brain tab is one centered vertical stream (`max-w-4xl`, 896 px), styled like a
standalone AI product: user rows and AI rows are frameless text on obsidian, paragraphs
breathe (`space-y-12` between turns), lists use gold markers, `**bold**` renders as tracked
white signposts, and every `[thumb:ID]` the model cites is pulled OUT of the text into its
own media row under the paragraph. If the radar knows that video the card becomes an inline
**spotlight slate** (`[ OUTLIER_RADAR // TARGET_IDENTIFIED ]`: thumbnail | multiple ·
channel / title / views vs normal / Convert). There are no side panels any more: the outlier
radar is itself a slate in the stream (top line → *Radar* brings it to the bottom), idea
batches and "what is hitting" reports are AI turns, the quick prompts sit loosely at the
top and fade out on first use (*Prompts* brings them back), and the radar terms / standing
notes / reset live behind *Settings*. The console is fixed to the viewport floor; the send
arrow only turns gold once there is text or an attachment. Images can be attached (button,
paste, or drop onto the console); they are downscaled to 1600 px client-side and go to
Gemini with the message (`/api/strategy/chat` `images[]`).

Styling is Tailwind v4, compiled offline: source `tailwind/brain.css` → `static/brain.css`
via **`build-css.cmd`** (installs `tailwindcss` + `@tailwindcss/cli` into `tailwind/
node_modules` on first run, then ~100 ms per build). Run it after touching any `st-*` /
utility class in `templates/index.html` or `static/app.js`. Two things the source file
pins on purpose: the app's root font-size is 14 px, so the rem-based Tailwind scales
(`--spacing`, containers, text sizes, radii) are overridden in px; and the utilities are
emitted **unlayered**, because `style.css` is unlayered and a layered utility would lose
to its `button {}` / `textarea {}` rules regardless of specificity. `amber-*` is remapped to
the champagne gold. While the brain is the active section, `body.brain-active` swaps the
whole page onto the dark token set, whatever the theme toggle says.

## Strategy brain v2 (2026-09-10) — the outlier radar

The brain no longer answers from a fixed digest. Before every reply it reads:

1. **The tracked network** (store): every channel's numbers, top outliers, newest uploads,
   and a learned style card for the focus channel (title length, caps, emoji, Shorts share,
   recurring words).
2. **The outlier radar** (`sf/radar.py`), two feeds. *Inside the network* = every tracked
   channel's recent uploads scored against the median of that channel's previous 30 uploads
   of the same format (zero quota). *Beyond the network* = YouTube Data API `search.list`
   (order=viewCount, last 30 days, region US, longform buckets 4-20 min and 20 min+) for each
   niche term, then `videos.list` for real stats and a per-channel baseline (median of its
   recent uploads, cached 24 h), so the multiple is against that channel's OWN normal - a
   40k channel doing 900k outranks a 2M channel doing 1M. Terms come from the network's own
   tags (counted once per channel; generic words and channel names dropped) unless pinned in
   the radar settings. Cost ~1.7k units per refresh with 8 terms; auto-refreshes when older
   than 24 h, "Also scan Shorts" doubles the searches.
3. **Its own memory**: every title it has pitched and every outlier id it has already
   converted (from the chat's `[thumb:ID]` tags and the idea board's `ref_id`). Pitched
   titles are injected as a never-repeat list and converted ids are hidden from the next
   radar brief, so successive batches land on new source material. Chat history and
   standing notes persist server-side (`/api/strategy/history`, `/api/strategy/settings`,
   `/api/strategy/reset`).

Every chat reply ends with a hidden `[[pitched: ...]]` line that the server strips and
stores. The **idea board** (`/api/strategy/ideas`, "Convert →" on any radar row =
`seed_video`) returns structured pitches (title, mechanism, hook, why with the real multiple,
reference id validated against the store/radar, thumbnail concept, on-thumbnail text, a full
art-direction prompt, series angle) and **Paint thumbnail** (`/api/strategy/thumb`) renders
it with the thumbnail generator using the saved face/character/style references.
"What is hitting right now" (`/api/strategy/report`) is a read of both feeds with no pitches.

## Phone app (2026-09-10)

`/m` is the app-shaped interface: a PWA (manifest + service worker + icons) with five tabs -
Home (network totals + channels; tap a channel to focus the brain on it), Brain (the same
Studio Brain: persisted chat, prompts, idea board with Paint thumbnail + Add to plan, radar
slates inline), Radar (both feeds, Convert -> ideas, refresh), Plan (your content plan +
the next 14 days of scheduled uploads) and Alerts (dismiss). Phones hitting `/` are sent to
`/m` (`?desktop=1` keeps the full site). The service worker caches only the shell; every
API call is live.

Install on a phone: open the hosted URL (Render) or `http://<pc-ip>:5800/m` on the same
Wi-Fi, log in, then Chrome: menu -> Add to Home screen; iPhone Safari: Share -> Add to Home
Screen. It opens full-screen with its own icon. The extension is unaffected.

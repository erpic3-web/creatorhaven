## Settings

All in `chrome.storage.sync`, defaults in `SF.SF_DEFAULTS` (lib/common.js), seeded by
`bg.js` on install without overwriting existing values, read everywhere through
`SF.withDefaults()` (type-coerced). Keys exactly as specified: `siteUrl`, `token`, `discordUrl`
and the toggles `confirmSignOut, exactDates, realNames, subCounts, feedCleaner, shortsRedirect,
dontRecommend, thumbDownloader, playlistSearch, videoTags, appearance (+appearanceAccent,
appearanceFont, appearanceCompact), sizeCustomizer (+playerWidthPct, commentsFontPx), favorites,
studioProbe, studioDiscordButton, streamerMode`.

**One deliberate deviation:** the spec names both the *favorites toggle* and the *starred-channel
array* `favorites`. The toggle keeps the name `favorites`; the array is stored as `favoritesList`
(`[{title, href}]`) so a boolean and an array never share a key.

## Features implemented

Every DOM feature: gated by its toggle (live via `storage.onChanged`), idempotent through
`data-sf-*` markers / `sf-*` classes, re-run by a debounced `MutationObserver` (300 ms YouTube,
400 ms Studio) + YouTube's `yt-navigate-finish` / `yt-page-data-updated` events + a 1 s URL poll,
and wrapped in `safe()` → one `console.warn('[SF] <feature>', err)` per distinct error, never a
throw. Each feature also has an `off()` that removes what it added when the toggle is turned off.

### youtube.com (`content/yt.js`)
1. **confirmSignOut** — capture-phase click listener; `composedPath()` walk (works through shadow roots) for `a[href*="/logout"]` or a short element whose text is "Sign out"; `window.confirm("Sign out of all Google accounts?")`, `preventDefault` + `stopImmediatePropagation` on cancel.
2. **exactDates** — `/watch` only; text nodes under `ytd-watch-info-text` / `ytd-watch-metadata #info` / `#info-strings` (description body, comments excluded) matching `SF.relativeDateRegex` get ` · Sep 8, 2026, 3:41 PM` (`Intl.DateTimeFormat en-US`, local time) from `meta[itemprop=datePublished]` → `meta[itemprop=uploadDate]` → `"publishDate":"…"` in an inline script that also names this video id. Marker `data-sf-dated=<videoId>` on the parent; if YouTube re-renders the text over our span the marker is dropped and it is re-added. **Stale-metadata guard:** `<head>` microdata is written for the first video, so after SPA navigation `meta[itemprop=identifier]` / canonical are compared with the current id; if they disagree the extension falls back to the date-only tooltip YouTube renders for the *current* video ("3,215 views • Sep 8, 2026") and never shows a wrong value. Feeds/search dates are not attempted in v1: those cards carry no per-item publish timestamp in the DOM, so it would need one API call per card (a later site feature).
3. **videoTags** — `meta[property="og:video:tag"]` → `div.sf-tags` ("Tags (n): …") after `ytd-watch-metadata #bottom-row`; chip click copies (clipboard API with `execCommand` fallback) and toasts; zero tags → nothing; rebuilt per video id, same stale-metadata guard.
4. **thumbDownloader** — `⬇ Thumbnail` + `⧉` pill appended to `#top-level-buttons-computed` (fallback: fixed bottom-right, auto-re-homed when the row appears). Click → bg `thumbBest` walks `maxresdefault → sddefault → hqdefault → mqdefault → default`, skipping 404s and the 120×90 placeholder (Content-Length < 3000; body measured when the header is missing) → `window.open` in a new tab (popup-blocked → URL copied instead); `⧉` copies the URL. No `downloads` permission.
5. **playlistSearch** — `/playlist`: search input inserted above `ytd-playlist-video-list-renderer`; case-insensitive substring on `#video-title`; rows hidden via `data-sf-pl-hidden`; re-applied on every DOM pass so lazy-loaded rows obey the filter; `keydown` stopped so YouTube hotkeys don't fire while typing; "n / total" counter.
6. **feedCleaner** — `html.sf-feed-clean` + CSS for the structural cases (`ytd-reel-shelf-renderer`, `ytd-rich-shelf-renderer[is-shorts]`, guide/mini-guide "Shorts" entries via `:has()`), JS marks `data-sf-shelf="hide|keep"` on `ytd-rich-shelf/section/shelf-renderer` by header text (`SF.shelfBlockRegex`: Shorts / Playables / Latest YouTube posts / Breaking news) and on guide entries by title/aria-label. Shelves whose header has not rendered yet are left unmarked and re-examined.
7. **shortsRedirect** (off) — `/shorts/<id>` → `location.replace('/watch?v=<id>')`, at document_start, on settings change and on every navigation event.
8. **realNames + subCounts** — handle slots `ytd-comment-view-model #author-text`, `ytd-comment-renderer #author-text`, `ytd-channel-name #text` whose text starts with `@`; cache `hn:<@handle lowercase>` in `storage.local` (`{title, subscribers, id, ts}`, 7 days; negative rows 1 day); misses batched ≤ 50 → bg `channels` → `GET {siteUrl}/api/ext/channels?handles=%40a%2C%40b` with `X-SF-Token`; response keys normalised case-insensitively. Display name replaces the visible text (original handle kept in `title` + `data-sf-handle`), `span.sf-subs` "· 1.2M" via `SF.compactNumber` when subCounts is on. Empty token → one `console.info`, cached names still applied; site failure → one info line and a 5-minute back-off. Runs when either toggle is on; the badge/name parts follow their own toggle.
9. **dontRecommend** (off) — `mouseover` (capture) injects one `button.sf-dnr` "✕" per `ytd-rich-item-renderer` (CSS shows it on hover); click → the card's own `ytd-menu-renderer` button, then polls up to 1.5 s (100 ms) for a menu item (`ytd-menu-service-item-renderer, tp-yt-paper-item, [role=menuitem], yt-list-item-view-model`) matching `/don.t recommend channel/i` and clicks it; otherwise closes the menu (backdrop click + Escape) and toasts "Not available here".
10. **favorites** — Subscriptions section found by its `h3`/`#guide-section-title` text (fallback: the section with `#expandable-items`); ☆/★ button on every channel entry (`a#endpoint` href starting `/@`, `/channel/`, `/c/`, `/user/`); `div.sf-favorites` block inserted above the section, rebuilt only when the list signature changes; entries are plain links with a ✕; stored in `storage.sync.favoritesList`.
11. **appearance** (off) — `<style id="sf-appearance">` overriding the accent tokens (`--yt-spec-brand-button-background`, `--yt-spec-call-to-action`, `--yt-spec-static-brand-red`, `--yt-spec-red-indicator`, `--yt-spec-icon-active-button-link`, `--yt-spec-themed-blue`, `--yt-spec-brand-icon-active`, plus the player progress bar), an optional `font-family` on `html, body, yt-formatted-string, …`; compact mode reads the computed `--ytd-rich-grid-items-per-row` on each `ytd-rich-grid-renderer`, sets +1 inline and `--ytd-rich-grid-item-margin: 8px`, remembering the original in `data-sf-compact`. Documented best-effort: YouTube renames tokens between builds.
12. **sizeCustomizer** (off) — reads the computed `--ytd-watch-flexy-max-player-width/height` on `ytd-watch-flexy` once (stored in `data-sf-orig-*`), sets them inline scaled by `playerWidthPct` (clamped 50–200); `<style id="sf-size">` sets the comment font size (`#content-text`, clamped 8–40 px). Restored on toggle-off / value change.

### studio.youtube.com (`content/studio.js` + `studio_probe_main.js`)
Studio's `ytcp-*` elements use real open shadow roots, so lookups use `deepQuery()` (descends into every `shadowRoot`), injected UI is styled inline (a document stylesheet does not reach shadow trees), and the single observer is attached to every shadow root the walker meets.
13. **confirmSignOut** — same guard as 1 (Studio's avatar menu is a cross-origin Google iframe, so only sign-out links in Studio's own DOM are covered — documented).
14. **studioDiscordButton** — inline-styled "Discord" pill inserted first in `#right-section` (fallbacks `ytcp-header #header`, `#header`, then fixed top-right; a floating pill is re-homed for up to 60 s once the header's shadow tree renders); `target=_blank rel=noopener`; hidden unless `discordUrl` is an http(s) URL.
15. **streamerMode** (off; **Alt+Shift+H** toggles and persists to storage.sync so the popup follows) — walks `#main-container` (fallback `body`) including shadow roots, splits every text node with `SF.segmentNumbers` (2+-digit runs, optional `,` `.` and K/M/B suffix) into `<span class="sf-blur" data-sf-blur style="filter:blur(6px)!important">` segments; idempotent by construction (digits only survive inside skipped spans); re-applied on mutations (including `characterData`) in light and shadow DOM; off → spans unwrapped and parents `normalize()`d. Budgeted at 150 k nodes per pass.
16. **studioProbe** — MAIN-world script wraps `window.fetch` (reads `response.clone().text()`, returns the ORIGINAL promise/Response untouched) and `XMLHttpRequest.prototype.open/send` (URL captured in `open`, `load` listener in `send`). For URLs containing `/youtubei/v1/` it posts `{ source:"sf-probe", url:<path only>, status, keys:<top-level keys>, size, hits, ts }` to `location.origin`; `hits` = keys matching `/realtime|last48|last60|fortyEight|sixtyMin|engaged|monetiz|adBreak|midroll/i` (depth ≤ 8, ≤ 5000 nodes, ≤ 200 hits) with JSON path and number / ≤ 40-char string values. The isolated script relays each entry to bg (`{type:"probe", entry}`) and, when there are hits, `{type:"realtime", channelId:<UC… from the pathname>, hits, url, ts}`; bg POSTs `{ channelId, samples, url, capturedAt }` to `/api/ext/realtime` at most once per 5 s, fire-and-forget (skipped when no token). The probe can be switched off live via a `sf-probe-ctl` message; it never installs twice (`window.__sfProbeInstalled`, non-enumerable) and every line is try/catch-wrapped. Log = `storage.local.probeLog`, ≤ 300 entries, deduped by `url+status` with `count`, first-seen `keys`, `size`/`lastSize`, `firstSeen`/`lastSeen`, hits unioned by path (≤ 50). bg batches writes (300 ms) so a Studio page load's burst is one read-modify-write.

### Popup
Dark 380 px panel: site card (URL, token, **Test connection** → bg `ping` → "Connected: <app> v<version>" or the error; non-local hosts trigger an `optional_host_permissions` request inside the click; **Open site**), toggles grouped YouTube / Appearance & size / Studio, accent colour + font + compact, player-width and comment-font sliders (sub-controls dim when their master is off), Discord URL, favorites count, probe stats (`n endpoints · m responses · h hits · last HH:MM`), **Export probe log** (JSON to clipboard) / **Clear**, **Thumbnail Tester** button. Every change saves to `storage.sync` immediately with a "Saved" flash.

### Thumbnail Tester (`tester.html`)
Client-side only. 1–4 images via file picker, drag-and-drop anywhere on the page, or paste; labelled A/B/C/D. Title, channel, views, age, duration, theme (light / dark / both). Renders at YouTube's metrics: home grid (360 px, 16:9, 12 px radius, 36 px avatar, 16 px/500 title), sidebar "Up next" rows (168 px thumbs, interleaved with grey competitor rows), search result (360 px thumb, 18 px title, 24 px avatar, snippet), mobile feed (412 px phone frame, full-width thumb), and "Among competitors": 8 grey competitor cards + yours at random positions, **Shuffle** re-seeds. Light and dark side by side. Object URLs are revoked on remove/clear.

### bg.js
Message handlers: `ping`, `channels`, `realtime`, `probe`, `probe:get`, `probe:stats`, `probe:clear`, `thumb`, `thumbBest`, `getSettings`, `setSettings`. Every fetch goes through `fetchWithTimeout` (AbortController, 10 s) and collapses to `{ok:false, error}`; the listener wraps handlers in a promise chain so callers always get an object, never an exception. Badge: green "•" after a successful ping, cleared otherwise; pinged on install, startup, siteUrl/token change and a 5-minute alarm; a daily alarm prunes expired `hn:*` rows. Cross-browser: `const api = globalThis.browser ?? globalThis.chrome`; all APIs used in promise form (`storage.*`, `runtime.sendMessage`, `alarms`, `action`, `tabs.create`, `permissions.request`); `importScripts('lib/common.js')` only when running as a Chrome service worker (Firefox loads it through `background.scripts`).

## Known limits
- exactDates / videoTags after SPA navigation depend on `<head>` metadata that YouTube may not refresh; the extension detects the mismatch and shows a date-only fallback (from the info tooltip) or nothing — never a wrong value. Feed/search cards get no dates in v1.
- appearance / sizeCustomizer are best-effort CSS-variable overrides.
- streamerMode blurs runs of 2+ digits (so "5K" or a single-digit count is not blurred; "12 km" blurs the "12"). Studio pages are large; the per-pass budget is 150 k nodes.
- Studio sign-out lives in a cross-origin iframe the content script cannot reach.
- Firefox MV3: host permissions must be granted by hand; `world: "MAIN"` needs Firefox 128+; `storage.sync` works because `browser_specific_settings.gecko.id` is set.
- `realtime` POSTs are skipped when the token is empty (the site would reject them anyway).


## 2026-09-10 — Tile (with title) is a real feed tile

`Download ▾ → Tile (with title)` used to burn the title into the thumbnail. It now composes the video the way the YouTube feed shows it: rounded thumbnail (1280x720), round channel avatar, title (max 2 lines, ellipsis), channel name, `views • age`, on the page's light/dark theme (~1280x944 png). Channel/avatar/meta are read from the card DOM without class names (first `/@handle` or `/channel/` link, the ggpht image outside the thumbnail, the `views` / `ago` text lines). Avatars are cross-origin, so they are fetched as a blob (direct, else the new `imageBlob` background handler; `https://yt3.ggpht.com/*` added to host_permissions - **reload the unpacked extension** to pick up the new permission). No avatar = a colored initial circle.
